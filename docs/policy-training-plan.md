# Multi-team doubles policy implementation plan

Written before implementation on 2026-10-12. Scope: Python policy, training and evaluation plus minimal observation metadata/metrics bindings where necessary. Preserve the Rust battle rules, Speed inference, tournament scraper, guessed spreads and existing randomized team variation. Do not implement search or run long training allocations.

## Decisions and order

1. **Model configuration:** small (128 wide / 3 layers), medium (256 / 4), large (384 / 6), small by default. Persist explicit configuration; reject incompatible resume options. Speed inference remains enabled; an ablation masks inferred Speed ranges/item possibilities and relative ordering while retaining ordinary known stats and dex data. Add named metadata for those feature slices.
2. **Policy experiments:** independently configurable semantic first-action conditioning and joint four-Pokémon preview scoring; recent public observation-history tokens (not a reconstructed full battle event log); auxiliary opponent-action prediction and hidden item/ability/move prediction. Prediction feedback is a separate option. History must work in collection, PPO evaluation, frozen opponents and the Showdown client. Hidden labels come only from the opposite side's own observation and are never actor inputs. Move prediction uses set labels. Baseline experiments are off by default.
3. **Training league:** default mixture current 50%, frozen checkpoints 40%, scripted 10%; opponents stay assigned for a complete episode. Keep recent and older checkpoints, with bounded model cache. PPO updates only learner-generated decisions, including correct credit across wait requests. Opposing actions provide supervised labels, not off-policy PPO samples. Self-play can still use both sides. Save opponent sampling state and manifest.
4. **Multi-team evaluation:** preserve the existing sampler; add a deterministic split utility grouping identical/near-identical species compositions, optional archetype labels, and training/evaluation overlap checks. Existing pools can be used unchanged. Detailed evaluation runs use fixed seeds, alternating sides, frozen opponents, outcome confidence intervals, per-team/archetype/matchup results, value calibration, timeout counts and bounded decision traces for inspection. Mark lookahead as privileged. Save matchup matrices to expose forgetting/cycles.
5. **Training metrics:** phase-specific normalized entropy, nonnegative approximate PPO KL, clipping, gradients, auxiliary losses, explained variance, terminal value calibration in evaluation, episode length, ties versus timeouts, opponent mixture, and cumulative valid decisions. Time simulation/transfers/inference/updates separately; report full-loop decisions/sec, CUDA memory and available utilization metrics rather than claiming GPU performance on this CPU host.
6. **Reproducibility and cluster use:** checkpoint Python/NumPy/Torch CPU/CUDA RNGs, optimizer, schema/layout/dex fingerprints, run configuration, pool hashes, league manifest and counters. Exact mid-battle resume requires simulator serialization not currently available: document episode restart and deterministic continuation from update boundaries instead of claiming exact continuation. Slurm signals save at a safe rollout/update boundary. Provide an Oscar template with resource placeholders and no invented partition/GPU entitlement.
7. **Benchmark tools:** environment/inference/collection/update benchmark with model size and batch/CPU sweeps; fixed-checkpoint evaluation CLI; paired multi-seed experiment configuration runner and Showdown-client JSON outcome logging. No automatic external challenges or long cluster jobs.
8. **Validation and documentation:** meaningful tests for presets, Speed ablation, experimental likelihood consistency, history isolation/reset, hidden-label separation, league episode assignment/learner masks, split leakage, evaluation accounting/calibration, and checkpoint resume. Run existing Python tests and focused integration smoke training/evaluation/benchmark jobs. Document commands and limitations. Record actual checks and model counts after implementation.

## Acceptance

A default small-policy run trains across the existing team pool against a real checkpoint league. Each optional experiment can be enabled alone. Old baseline model snapshots remain loadable; new checkpoints record their observation/model contracts. Held-out evaluations produce reproducible JSON reports with actual completed game counts and stratified outcomes. Search is absent. GPU and live Showdown checks are explicitly unverified until run on the user's resources.

## Completion record

All eight steps were implemented. See [usage and contracts](policy-training.md) and [validation evidence](policy-training-validation.json). The default remains the small model with Speed information and a real training league. Experiments are opt-in; no search was added.

Implementation details: history uses public decision snapshots rather than exact event tokens; composition splitting keeps spread/item/move variants of the same six species together, but does not cluster five-of-six overlaps. Frozen training candidates are the latest two, middle and oldest snapshots. These limits are documented explicitly.

Validation: 28 Python tests pass with one live-server test skipped, 18 experiment checks pass, and 10 focused Rust environment checks pass. A debug-mode lookahead baseline tournament was stopped and excluded from the focused rerun. CLI smoke checks cover training with all experiments, resume, held-out evaluation, hardware benchmark and multi-seed experiment command generation. The Python release extension was rebuilt. GPU/Oscar execution, live-server play and competitive strength remain to be measured on the user's resources.
